# 产品定位与边界

## 1. 一句话

LumaDuo 是给上下双屏 Android 掌机用的 Moonlight 串流客户端：**上屏看电脑画面，下屏用手柄操作全部功能**。

## 2. 目标用户

### 核心用户

- 拥有 Retroid Pocket Duo、AYN Thor 等双屏 Android 掌机
- 有一台带 NVIDIA/AMD/Intel 显卡的 Windows PC
- 已在 PC 上使用或愿意使用 Foundation Sunshine
- 希望躺着/通勤时玩 PC 游戏，但不想带笔记本
- 接受局域网串流，也愿意为外网访问配置 EasyTier

### 次要用户

- 单屏 Android 掌机/手机用户：使用单屏模式
- 已有 Moonlight/Sunshine 生态、想换一个更适合掌机 UI 的客户端
- 喜欢折腾虚拟组网、但不想自建中继

### 非目标用户

- 需要 4K/144Hz 有线串流的桌面用户（可用桌面 Moonlight）
- 需要多人账号、云游戏库、社交功能的用户
- 需要 root、系统级注入、破解主机的用户

## 3. 用户任务

1. **第一次连接**：发现或手动添加 PC → 输入 PIN/扫码 → 看到应用列表
2. **局域网串流**：选应用 → 上屏出画面 → 手柄直接控制游戏
3. **本地操作**：按 Return 或点下屏菜单 → 下屏调分辨率/码率/音频/输入 → 回到游戏
4. **串流中查看状态**：默认落在只读“状态”页，确认 FPS、延迟、码率、网络/本机状态；主机实时负载不可得时明确显示“未提供”
5. **远程串流**：客户端开 EasyTier → PC 也加入同一网络 → 手动填 PC 虚拟 IP → 串流
6. **单人/观看**：不接手柄时也能用触摸完成主机管理、设置和启动
7. **单屏**：没有下屏时，视频全屏 + 控制台抽屉/覆盖层

## 4. 产品原则

1. **视频是主角**：上屏只放视频或首帧前的只读状态。没有 OSD、按钮、焦点。
2. **下屏是操作台**：所有可操作元素都在下屏；单屏时在唯一宿主上。
3. **手柄优先**：每个关键流程都能只用 D-pad/左摇杆 + B/A + 肩键完成。
4. **直通优先**：串流时手柄默认给 PC；本地 UI 是显式进入的“本地模式”。
5. **状态可见**：ModeBar 始终告诉用户“手柄在控制谁”。
6. **少层级**：主机 → 应用 → 串流，最多三层；设置是独立一级。
7. **不复制页面**：继承 bili-duo 的设计语言，但信息架构按 LumaDuo 的功能重新组织。
8. **可恢复**：断线、切后台、Presentation 重建、主机休眠都要有明确状态和重试入口。

## 5. MVP 功能

| 模块 | 功能 | 优先级 |
|---|---|---|
| 主机 | 局域网发现、手动添加、PIN 配对、QR 入口（有摄像头时） | P0 |
| 主机 | 最近连接、收藏/排序、编辑地址、删除 | P1 |
| 应用 | 获取应用列表、图标/名称、启动串流 | P0 |
| 串流 | H.264/H.265、1080p60、按设备支持 120Hz | P0 |
| 串流 | 上屏视频、下屏控制台、首帧/连接/错误状态 | P0 |
| 串流 | 默认只读状态页：客户端实测帧率/延迟/码率、网络/本机状态；主机静态信息可选；无可点击设置 | P0 |
| 串流 | 主机实时负载（可选 Host Bridge）：CPU/GPU/内存 | P1/可选 |
| 输入 | 手柄直通、本地模式、ModeBar、Return 打开本地菜单 | P0 |
| 输入 | 串流工具：触摸板、ASCII 键盘、快捷键（控制台/工具双态） | P0 |
| 设置 | 分辨率、帧率、码率、HDR、音频、输入、网络 | P0 |
| 网络 | EasyTier 配置、状态、虚拟 IP、复制配置/二维码 | P0 |
| 网络 | PC 端 EasyTier 配置生成（.2 地址、同网络名/密钥） | P0 |
| 单屏 | 视频全屏、控制台抽屉/覆盖层、同一套焦点 | 延期（D-043，项目稳定后） |
| 体验 | PiP、双屏亮度、串流常亮 | PiP 延期；亮度/常亮 P1 |
| 输入 | 数字键盘、ASCII 键盘、PIN/IP/EasyTier 输入 | P0 |
| 输入 | 保留 V+ 剪贴板同步；不扩展为文件传输 | P1 |
| 音频 | 7.1.4、麦克风、DualSense 反馈 | P2 |
| 显示 | Foundation 虚拟屏/多显示器选择 | P2 |
| 文件 | 文件夹共享/文件传输 | 不做 |

## 6. 明确不做

- UUYC 协议兼容、UUYC 签名、RTC、文件传输代码
- 自研 VPN / 中继 / NAT 穿透协议
- 皎月连集成（闭源、无 Android SDK）
- root / Shizuku 系统级注入
- 多语言（首发中文）
- 多路独立串流 / 超级屏
- 触屏虚拟按键作为核心输入

## 7. 成功标准

### M0

- 未修改 V+ 能在 RP Duo 上构建、安装、局域网串流
- 记录首帧、码率、延迟、HDR、双屏行为

### M0.5

- Duo/Thor 上 Presentation 能显示 Compose
- 手柄事件落点明确，无双响应
- Return/Back、IME、焦点行为符合预期

### MVP

- 第一次连接不需要读文档也能完成
- 1080p60 串流稳定；下屏操作不打断游戏（除非进入本地模式）
- 所有关键流程可纯手柄完成
- 没有“上屏控件/下屏控件”两套 UI
- 从主机列表到应用启动不超过 3 次确认
- 串流进入本地控制台时默认看到状态页；状态页不提供任何写操作，主机负载缺失时明确标注

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| Thor 固件差异 | 布局/焦点/IME 不兼容 | 能力探测 + M0.5 真机探针 + 双断点布局 |
| V+ 上游变动 | 合并冲突 | 私有仓库保留 upstream 历史；固定 baseline tag |
| 全面改包名 | JNI/反射断裂 | 分阶段改；保留 EasyTier 包名；真机 smoke test |
| EasyTier 配置复杂 | 用户放弃远程 | 复制配置/二维码、PC .2 预设、清晰错误文案 |
| 系统 IME 不可靠 | 无法输入 | 自绘数字/ASCII 键盘为主 |
| 主机实时负载不可得 | 状态页信息不完整 | 以客户端实测为主；主机负载标“未提供”；需要时再接 Host Bridge |
| GPL 合规 | 分发风险 | 保留 LICENSE/NOTICE/上游许可；源码可获取 |

## 9. 术语

- **上屏**：默认 display 0，只读视频
- **下屏**：第二块屏；Duo 上只能 Presentation，Thor 上可承载 Activity
- **本地模式**：手柄控制下屏 UI，暂停直通
- **直通**：手柄事件发给 PC
- **ModeBar**：下屏底部 28dp 状态条，显示当前输入所有者
- **Control Deck / 串流控制台**：串流时下屏的控制界面
- **状态页**：串流控制台最左的只读页；客户端实测 + 可选主机静态信息，不含写操作
- **Host Bridge**：可选的主机侧只读伴随服务；提供实时 CPU/GPU/内存，不修改 Foundation；MVP 不依赖
